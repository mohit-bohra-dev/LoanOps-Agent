# ADR-030 — Doc GraphRAG under kill gate (draft)

**Date**: 2026-10-15  
**Status**: Draft (pending approval)

## Context

ADR-025 deferred GraphRAG over the SOP/doc corpus: small corpus, citation risk from community summaries, non-deterministic local extraction, and EAKG already covering capability/graph questions. A product request asked to architect GraphRAG anyway and override ADR-025.

An architecture review found that **current measurement cannot tell whether GraphRAG helps**:

1. `_fix_citations` can turn arbitrary strings into `policy:` sources; `_TOOL_NAMES` still lists `search_policy` and omits `search_docs`.
2. Ragas faithfulness contexts are built from model citation snippets, not tool retrieval text.
3. Chunk ids hash absolute filesystem paths, so committed graph membership cannot resolve across checkouts.

Without fixing those, `citation_coverage` and faithfulness can stay green even if retrieval gets worse.

## Decision

**Conditional override of ADR-025**, scoped as follows:

1. **Ship first (no GraphRAG):** citation grounding validator; faithfulness contexts from tool results; `citation_groundedness` gate at 1.0 (new metric — does not lower existing thresholds); tool-name truth in golden/parser; corpus-relative paths; consolidate vector target on `docs`; ≥20 global/multi-policy golden items; baseline latency.
2. **Ship next:** wire existing reranker into `DocsService` (`candidate_k` constructor arg); deterministic `doc_links` + one-hop expand. Re-measure the global slice.
3. **Kill gate:** if the slice meets faithfulness ≥ 0.85 and citation_groundedness ≥ 1.0 after step 2, **do not build GraphRAG**. Record that ADR-025 is upheld under honest measurement. Optionally still accept a short form of this ADR documenting the measurement fixes only.
4. **Only if the kill gate fails:** enable community **summary routing** over the deterministic link graph (Louvain, seeded), with summaries never accepted as `policy:` sources; `GraphRagService` wraps `DocsService`; no `mode` on the LLM tool schema; missing/stale artifact fails closed to flat/local search.
5. **Only if summary routing helps and graph quality remains the limit:** LLM entity/relation extraction with content+model+prompt+schema cache, deterministic grounding filter on extractions, PII scrub with state/vocab allowlist, checked-in artifact under `data/graphrag/` **only for local `data/sops`**, refuse writing repo artifacts from Confluence sources. No new GraphStore Provider for doc entities in v1 (ADR-026 stays EAKG-only).

## Alternatives considered

| Alternative | Why not (for now) |
|-------------|-------------------|
| Full GraphRAG immediately | Cannot measure benefit; violates ADR-025 triggers |
| Named SPARQL graph for doc entities | Overkill for ~100–200 chunks; pollutes governed EAKG store |
| Env-var extract model override on cached chat factory | Extra approval and factory surface; process-scoped `LLM__*` sufficient |
| Expose `mode=local\|global` on `search_docs` | Reintroduces LLM routing variance the design avoids |

## Consequences

### Positive

- Measurement becomes capable of proving or killing GraphRAG.
- Cheap ADR-025 path gets an honest chance first.
- Citation trust becomes mechanical, not prompt convention.
- Any GraphRAG that ships keeps `policy:` citations bound to verbatim retrieved chunks.

### Negative

- Faithfulness scores may drop when contexts become real — thresholds must not be lowered to hide this.
- Path normalisation forces a one-time re-index (chunk ids change).
- Community artifacts will conflict across SOP branches; regenerate after merge.
- Optional GraphRAG still unlikely to win on a ~60-file procedural corpus.

### Neutral / process

- New metric gate and any later `GRAPHRAG__*` / `LoanOps.GraphRag` project require the usual AGENTS.md human approvals.
- This draft must be edited to match the **actual** kill-gate / gate2 outcomes before acceptance (narrow the Decision section to what shipped).
